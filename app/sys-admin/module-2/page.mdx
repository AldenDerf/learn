## What you need

- A Windows computer with VirtualBox installed.
- An Ubuntu Server VM that you can start and sign in to.
- Access to the VM window, called its **local console**.
- An Ubuntu account allowed to use `sudo`. This means it can run approved commands with administrator privileges.

We use two separate connections:

```text
Windows host
    |
    | Host-Only: host and VM communicate
    |
Ubuntu Server VM
    |
    | NAT: optional separate Internet connection
    |
Internet / package downloads
```

The lessons explain Host-Only and NAT before you configure them. Do not use Bridged mode for this lab: that would connect the VM to your physical school or home network.

## Our example address plan

| Device | Example address |
| --- | --- |
| Windows Host-Only adapter | `192.168.56.1/24` |
| Ubuntu Server Host-Only interface | `192.168.56.10/24` |

An **address plan** is a record of which device uses each address. Lesson 2.1 explains the numbers and `/24`. Interface names such as `enp0s8` are examples; your VM may use different names.

## Instructor note: prepare the lab image

The examples assume VirtualBox 7.x and Ubuntu Server 24.04 LTS. Confirm the classroom versions, permissions, and network setup before practice. This is a VirtualBox lab, not a WSL lab.

Check that `192.168.56.0/24` does not overlap the Windows computer's existing local network or VPN (a connection to another private network). Confirm that the chosen addresses are unused. If another subnet is assigned, update the examples consistently.

Later, DHCP uses `.100`–`.150` for automatic addresses and `.20` for a reserved client. Keep the host `.1` and server `.10` outside that range. Disable VirtualBox's built-in DHCP only on this dedicated lab network before running the classroom DHCP server.
