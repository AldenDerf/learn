# 👥 Module 3: Users, Groups & File Permissions

Multi-user operating systems require strict permission schemes to protect sensitive configuration and system files.

---

## Permission Triad: Owner, Group, Others

When you run `ls -l`, each file displays a 10-character permission string:

```text
- rwx r-x r--   1 student faculty  4096 Sep 12 10:00 notes.txt
  └───┬───┘
   Owner: read, write, execute (rwx = 7)
       Group: read, execute (r-x = 5)
           Others: read only (r-- = 4)
```

### Numerical Permission Values:
- **`r` (Read)** = 4
- **`w` (Write)** = 2
- **`x` (Execute)** = 1

---

## Modifying Permissions (`chmod` and `chown`)

### Examples:

```bash
# Give owner full control, group and others read-only (744)
chmod 744 script.sh

# Make a script executable for everyone
chmod +x deploy.sh

# Change ownership of a directory to user 'admin' and group 'faculty'
sudo chown -R admin:faculty /var/www/html
```

---

> 💡 **Best Practice:**
> Avoid using `chmod 777` in production environments as it allows any user to read, write, and execute files on the server!
