# Chapter 2: Scalable REST API Architecture with Express.js

This chapter turns your foundational knowledge into an organized, well-structured Express backend API. You will learn how to run server-side TypeScript, master the mechanics of HTTP messages across the network, operate a typed web server, trace requests from arrival to response, design predictable RESTful resource pathways, and separate routing definitions from controller and business logic.

---

## 🎯 Syllabus Outcomes

After completing this chapter, you should be able to:

- **Orchestrate a Node.js web server** and handle standard HTTP request/response parameters.
- **Describe the HTTP request/response lifecycle** and the six architectural REST constraints.
- **Design RESTful pathways** following architectural separation of concerns.
- **Build an Express service** using typed routers, modular controllers, and runtime validation.

## 📚 Handouts & Modules

### Foundation Prerequisites

#### 1. [Prerequisite 1: Running Your First Node.js + TypeScript Program](./first-program)
Establish the backend developer mental model: understand Node.js, TypeScript, and `pnpm`; initialize a workspace in PowerShell; install development tools; write typed functions; and run backend code using `package.json` scripts.

#### 2. [Prerequisite 2: Understanding HTTP Requests & Responses](./http-requests-responses)
Learn the anatomy of web communications before writing server code. Master the client-server request-response lifecycle, HTTP methods (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`), path parameters vs. query parameters, headers, JSON bodies, and status codes (`200`, `201`, `400`, `404`, `500`).

### 2.2 REST Constraints & Architectural Concerns

Start with **[2.2.1 Understanding REST API Design](./understanding-rest-api-design)**. Use the Student Information API from Lab 2.1 to learn why resource names and HTTP methods make routes easier to understand. Then read **[2.2.2 REST Constraints — Explained Simply](./rest-constraints-explained-simply)** to see the broader REST design boundaries. Next, use the supporting **[Tutorial: Testing REST API Requests with Postman](./testing-rest-api-requests-with-postman)** to send and inspect requests locally. Continue with **[2.2.3 Separation of Concerns with Express](./separation-of-concerns-with-express)** to organize that working API into server, routes, and controllers. Finally, complete **[Lab 2.2 — Separating Routes and Controllers in Express.js](./lab-2-2)** to independently refactor a Courses API into routes and controllers.

- **Laboratory Output 2.2:** Refactor a working one-file Express API into modular route definitions and controller functions, verify endpoints using Postman, and trace the request flow through the separated architecture.

## 💡 Practical Advice for Students

1. **Don't just read—type and run:** Backend development is muscle memory. Run every PowerShell command and verify the terminal output yourself.
2. **Design before coding:** Complete the prerequisites and Lab 2.1, then plan the resource routes in 2.2.1 before writing more Express code.
3. **Use isolated lab folders:** Keep your laboratory exercises in `C:\ite303-labs\` so your workspace remains organized throughout the semester.
