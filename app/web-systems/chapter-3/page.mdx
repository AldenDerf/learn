# Chapter 3: Backend Data Persistence with PostgreSQL

Start with **[3.1 Connecting Express to Supabase PostgreSQL](./connecting-express-to-supabase-postgresql)**. Extend your Chapter 2 Student Information API so its two GET endpoints read real student rows from Supabase.

Continue with **[3.2 Creating Student Records with POST and PostgreSQL](./creating-student-records-with-postgresql)** to validate JSON requests and save fictional students with a parameterized SQL INSERT.

Continue with **[3.3 Updating and Deleting Student Records (PUT & DELETE)](./updating-student-records-with-put-and-postgresql)**. This instructor-review draft combines the concepts, guided code, tests, and submission activity in one tutorial for the same Student API project.

Finish the chapter with **[3.4 Deploying Your Student REST API Using GitHub and Render](./git-github-and-preparing-for-deployment)**. Prepare your existing Activity 3.3 CRUD API for production (`process.env.PORT`, build/start scripts, `.gitignore`, and `.env.example`), publish it to GitHub using GitHub Desktop, deploy a live Web Service on Render with `DATABASE_URL`, verify all CRUD endpoints against your public HTTPS URL in Postman, and document your AI-assisted troubleshooting workflow. PATCH remains optional.
