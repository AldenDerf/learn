## Overview

In lesson 2.2.3, you saw how a growing Student Information API was reorganized by separating routes from controllers. Now you will apply that same architecture independently to a different resource: **Courses**.

You are given a working, single-file Express server. Your task is to refactor it into dedicated route and controller modules without changing its public endpoints or response behavior.

This activity assesses your ability to apply **Separation of Concerns in Express.js**:
- Keep `server.ts` focused on application configuration, middleware, and route mounting.
- Define HTTP method and path mappings in an Express Router (`courseRoutes.ts`).
- Isolate request handling and response logic in controller functions (`courseController.ts`).
- Verify that refactored endpoints behave identically using Postman.

## The Scenario

A university department wants a simple **Course API** to look up courses, filter courses by academic program, and accept updates.

The department's developer wrote a complete, working version in one file: `src/server.ts`. The API already handles all five required HTTP operations. However, having route matching, request parsing, and response creation packed into one file makes it difficult to maintain as more endpoints are added.

Your job is **not** to fix broken code. The starting server already works. Your job is **refactoring**: reorganizing the working code into a clean, modular architecture.

There is **no database** in this lab. All responses return truthful acknowledgements. POST, PUT, and DELETE confirm the request without pretending to save, alter, or remove records.

### The Working `src/server.ts`

Create `src/server.ts` and paste the starting code below. Run `pnpm dev` to verify that it starts without errors.

```typescript
import express from 'express';
import type { Request, Response } from 'express';

const app = express();
const PORT = 4000;

// Middleware to parse incoming JSON request bodies
app.use(express.json());

// 1. GET /courses - return course list or filtered by program query
app.get('/courses', (req: Request, res: Response) => {
  const program = String(req.query.program ?? 'all programs');
  res.json({
    message: 'Course list request received',
    program
  });
});

// 2. GET /courses/:id - return a specific course by ID
app.get('/courses/:id', (req: Request, res: Response) => {
  res.json({
    message: 'Course details request received',
    courseId: req.params.id
  });
});

// 3. POST /courses - receive new course data
app.post('/courses', (req: Request, res: Response) => {
  const { code, title, program } = req.body ?? {};

  if (
    typeof code !== 'string' || !code.trim() ||
    typeof title !== 'string' || !title.trim() ||
    typeof program !== 'string' || !program.trim()
  ) {
    return res.status(400).json({
      message: 'code, title, and program are required'
    });
  }

  res.status(200).json({
    message: 'Course data received; nothing was saved',
    course: { code, title, program }
  });
});

// 4. PUT /courses/:id - receive updated course data
app.put('/courses/:id', (req: Request, res: Response) => {
  res.json({
    message: 'Update request received; nothing was changed',
    courseId: req.params.id,
    updatedData: req.body
  });
});

// 5. DELETE /courses/:id - receive delete request
app.delete('/courses/:id', (req: Request, res: Response) => {
  res.json({
    message: 'Delete request received; nothing was removed',
    courseId: req.params.id
  });
});

// Start the server
app.listen(PORT, () => {
  console.log(`Course API running at http://localhost:${PORT}`);
});
```

### API Behavior Contract

The starting server implements this contract:

| HTTP Method | Path | Query / Body | Status | Expected Response Shape |
|---|---|---|---|---|
| `GET` | `/courses` | None | `200` | `{ "message": "Course list request received", "program": "all programs" }` |
| `GET` | `/courses?program=BSIT` | `program=BSIT` | `200` | `{ "message": "Course list request received", "program": "BSIT" }` |
| `GET` | `/courses/3` | Route parameter `:id` = `3` | `200` | `{ "message": "Course details request received", "courseId": "3" }` |
| `POST` | `/courses` | Valid JSON body | `200` | `{ "message": "Course data received; nothing was saved", "course": { ... } }` |
| `POST` | `/courses` | Missing or empty required field | `400` | `{ "message": "code, title, and program are required" }` |
| `PUT` | `/courses/3` | JSON body | `200` | `{ "message": "Update request received; nothing was changed", "courseId": "3", "updatedData": { ... } }` |
| `DELETE` | `/courses/3` | Route parameter `:id` = `3` | `200` | `{ "message": "Delete request received; nothing was removed", "courseId": "3" }` |

Test one or two requests in Postman now to confirm that the starting server works before you make any edits.

## Target Project Architecture

You will refactor the project into three distinct parts:

```text
course-api/
├── src/
│   ├── controllers/
│   │   └── courseController.ts
│   ├── routes/
│   │   └── courseRoutes.ts
│   └── server.ts
├── package.json
└── tsconfig.json
```

### Separation of Responsibilities

| File | What belongs here | What does NOT belong here |
|---|---|---|
| `src/server.ts` | App initialization, `express.json()`, mounting routes with `app.use()`, `app.listen()`. | Individual route definitions, request validation, response payloads. |
| `src/routes/courseRoutes.ts` | Express `Router`, mapping HTTP methods (`get`, `post`, `put`, `delete`) and paths to controller functions. | Request parameter parsing, business logic, formatting JSON responses. |
| `src/controllers/courseController.ts` | Controller functions that read `req.query`, `req.params`, and `req.body`, validate input, and call `res.json()`. | `app.listen()`, `Router` instantiation, route mounting. |
