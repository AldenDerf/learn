# 3.2 Creating Student Records with POST and PostgreSQL

**ITE 303 — Web Systems and Technologies 2**

**Self-paced tutorial and activity · Estimated time: 90–120 minutes**

## What you will build

Last time, your Student Information API used **GET** to read real students from Supabase PostgreSQL. Today, you will make **POST /students** save a new fictional student to the same database.

```text
Postman POST /students
   ↓ JSON request
server.ts → studentRoutes.ts → studentController.ts
                                  ↓
                    INSERT INTO students (...) VALUES (...)
                                  ↓
                       PostgreSQL / Supabase
                                  ↓
                     201 Created + new student
```

You will work in your **Student Information API practice project**, **not** inside the Learn website. Keep the two database-backed GET handlers from [Lesson 3.1](/web-systems/chapter-3/connecting-express-to-supabase-postgresql). ## 2. Understand the POST request (10 minutes)

GET asks for data. POST sends data for the server to create something new.

Send a request to `POST http://localhost:4000/students`. Under Postman **Body → raw → JSON**, use fictional details:

```json
{
  "student_number": "2026-006",
  "first_name": "Faye",
  "last_name": "Mendoza",
  "course": "BSIT",
  "year_level": 2
}
```

The `id` is intentionally absent: **PostgreSQL assigns it**. Because you are sending JSON, Postman should send `Content-Type: application/json`.

The Express JSON middleware reads this request and makes it available as `req.body`. In the POST handler, `req.body` is the data sent by Postman. We must check it before saving anything.

**Think:** Why should users not pick their own database-generated IDs?

## 4. Make POST save to PostgreSQL (25–30 minutes)

Open `src/controllers/studentController.ts`. **Keep both GET functions from Chapter 3.1.** Keep your existing Express `Request`/`Response` imports and the `pool` import from `../db`. Replace **only the old acknowledgement-only `createStudent` handler** with the following.

First, the handler checks that Postman sent a JSON object. It then checks the four text fields and `year_level`. A valid year level is a positive whole number, such as `1` or `2`. Chapter 3.1's table has no maximum-year rule. The SQL uses `$1` to `$5` as places for the five checked values; `pg` sends the values separately from the SQL text. `RETURNING` gives us the new row, including the `id` made by PostgreSQL.

```typescript
export async function createStudent(req: Request, res: Response): Promise<void> {
  // Get the data sent by Postman
  const body = req.body;

  // Make sure the data is a JSON object
  if (typeof body !== 'object' || body === null || Array.isArray(body)) {
    res.status(400).json({ message: 'A JSON object is required' });
    return;
  }

  const { student_number, first_name, last_name, course, year_level } = body;

  // Check the required text fields
  if (typeof student_number !== 'string' || student_number.trim() === '' ||
      typeof first_name !== 'string' || first_name.trim() === '' ||
      typeof last_name !== 'string' || last_name.trim() === '' ||
      typeof course !== 'string' || course.trim() === '') {
    res.status(400).json({ message: 'All text fields are required' });
    return;
  }

  // Check that the year level is a positive whole number
  if (typeof year_level !== 'number' || !Number.isInteger(year_level) ||
      year_level < 1) {
    res.status(400).json({ message: 'year_level must be a positive whole number' });
    return;
  }

  // Match each SQL place ($1 to $5) with one value below
  const sql = `INSERT INTO students
    (student_number, first_name, last_name, course, year_level)
    VALUES ($1, $2, $3, $4, $5)
    RETURNING id, student_number, first_name, last_name, course, year_level;`;
  const values = [
    student_number.trim(), first_name.trim(), last_name.trim(),
    course.trim(), year_level
  ];

  try {
    // Save the student to PostgreSQL
    const result = await pool.query(sql, values);

    // Send the saved student back to Postman
    res.status(201).json(result.rows[0]);
  } catch (error: unknown) {
    // Tell Postman if the student number is already used
    if (typeof error === 'object' && error !== null &&
        'code' in error && error.code === '23505') {
      res.status(409).json({ message: 'student_number already exists' });
      return;
    }

    // Send a safe message for other database errors
    res.status(500).json({ message: 'Could not create student' });
  }
}
```

### Read the code in plain language

- `req.body` receives the student's JSON from Postman.
- The checks stop blank names, missing fields, arrays, and invalid year levels. A rejected request returns **400 Bad Request** without saving a row.
- This practice API accepts positive whole numbers for `year_level`. A JSON number such as `2` passes; a string such as `"2"`, zero, or a decimal does not.
- `$1` through `$5` match the values in the array in the same order. Keep student input out of the SQL text.
- `INSERT INTO` saves a row. `RETURNING` asks PostgreSQL to send the new row back, including its generated `id`.
- `201 Created` means the save succeeded. If `student_number` is already used, PostgreSQL reports code `23505`; the API returns **409 Conflict**.
- Unexpected database errors return a safe **500** message; never send credentials or the raw database error to Postman.

**Checkpoint:** Your GET code is unchanged, and `createStudent` now contains a database `INSERT`.

### Is it really saved?

1. Stop Express with Ctrl+C.
2. Restart with `pnpm dev`.
3. Send GET `/students` again. Your created row should still be there.
4. Optionally confirm in Supabase SQL Editor:

```sql
-- Show the saved students and their generated IDs
SELECT id, student_number, first_name, last_name, course, year_level
FROM students
ORDER BY id;
```

The data survives restarting Express because it lives in **PostgreSQL**, not a JavaScript array.

## Troubleshooting

| Symptom | First thing to check |
| --- | --- |
| POST returns 404 | Is `router.post('/', createStudent)` present, and is the router mounted at `/students`? |
| `req.body` is undefined | Is `app.use(express.json())` before the router, and did Postman send raw JSON? |
| POST always returns 409 | Use a new fictional `student_number`, then query the table to inspect existing values. |
| POST returns 500 | Confirm the Chapter 3.1 database connection and table columns; inspect local server diagnostics without exposing secrets. |
| POST returns 201 but GET cannot find it | Make sure both routes use the same Supabase project and `students` table. |
| TypeScript reports missing imports | Keep the existing `Request`, `Response`, and `pool` imports from Lesson 3.1. |
